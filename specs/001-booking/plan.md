# Technical Plan: จองคิวตรวจสุขภาพ (Booking)

Spec: `SPEC-BKG-001`
อ้างอิง: `spec.md` v2

## 1. สรุปแนวทาง

- ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ (`FR-BKG-01`, `IF-IDP-01`)
- ระบบอ่านข้อมูลผู้รับบริการด้วย HN และแสดงเวลาว่างพร้อมที่นั่งคงเหลือภายใน 30 วัน (`IF-HIS-01`, `FR-BKG-01`)
- ระบบตรวจคิวซ้ำ ป้องกันการจองซ้อน และบันทึกหมายเลขคิวที่สัมพันธ์กับแพ็กเกจ (`FR-BKG-02`, `FR-BKG-03`, `FR-BKG-04`)
- ระบบส่งข้อความยืนยันแบบ asynchronous และ retry ตามจำนวน/เวลาที่กำหนดโดยยังคงการจอง (`IF-NOT-01`, `FR-BKG-05`, `NFR-REL-02`)
- การสร้างจริงต้องรอคำตอบ `Q-01`, `Q-03` ถึง `Q-08` ใน `spec.md` ก่อนล็อกพฤติกรรมที่เกี่ยวข้อง

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Booking` | `id`, `hn`, `package_id`, `appointment_date`, `time_slot_id`, `queue_number`, `status`, `created_at` | `FR-BKG-02`, `FR-BKG-04`, `IF-HIS-01` |
| `Package` | `id`, `name` | `FR-BKG-06`, `ASM-03` |
| `TimeSlot` | `id`, `package_id`, `appointment_date`, `start_time`, `end_time`, `capacity`, `remaining_capacity` | `FR-BKG-01`, `FR-BKG-03`, `FR-BKG-06`, `ASM-01` |
| `NotificationDelivery` | `id`, `booking_id`, `channel`, `attempt_count`, `last_attempt_at`, `status` | `FR-BKG-05`, `NFR-REL-02`, `IF-NOT-01` |
| `AuditLog` | `id`, `accessor`, `accessed_at`, `patient_code` | `DOM-PDPA-01`, `AC-BKG-06` |

`Booking` ต้องไม่มีฟิลด์เลขบัตรประชาชน โดยใช้ `hn` เป็นข้อมูลอ้างอิงภายในตาม `IF-HIS-01`

รายละเอียดฟิลด์ที่ยังขึ้นกับ `Q-03`, `Q-04`, `Q-06` และ `Q-08` จะยังไม่ล็อกจนกว่าจะได้รับคำตอบ

## 4. API / หน้าจอ

- `GET /booking/availability` รับ `package_id`, ช่วงวันที่ และผลยืนยันตัวตน; ส่งวัน/ช่วงเวลาว่างพร้อมที่นั่งคงเหลือ (`FR-BKG-01`, `IF-IDP-01`)
- `GET /booking/availability/{package_id}` รับแพ็กเกจใหม่; ส่งช่วงเวลาว่างที่คำนวณใหม่ (`FR-BKG-06`)
- `POST /bookings` รับ `hn`, `package_id`, `appointment_date`, `time_slot_id`; ส่งสถานะการจอง หมายเลขคิว หรือผลปฏิเสธพร้อมหมายเลขคิวเดิม (`FR-BKG-02`, `FR-BKG-04`)
- `POST /bookings/{booking_id}/confirm` รับคำยืนยันการจอง; ส่งผลสำเร็จหรือช่วงเวลาเต็มพร้อมตัวเลือก 3 รายการ โดยไม่สร้างรายการซ้อน (`FR-BKG-03`, `AC-BKG-03`)
- `GET /bookings/{booking_id}` รับรหัสรายการจอง; ส่งรายละเอียดการจองและหมายเลขคิว (`FR-BKG-04`, `DOM-PDPA-01`)
- หน้าจอเลือกแพ็กเกจ/วัน/เวลา แสดงที่นั่งคงเหลือและผลการเปลี่ยนแพ็กเกจ (`FR-BKG-01`, `FR-BKG-06`)
- หน้าจอยืนยันผลการจอง แสดงหมายเลขคิวหรือข้อผิดพลาดตามกรณี (`FR-BKG-02`, `FR-BKG-03`, `FR-BKG-04`, `FR-BKG-05`)
- Worker ส่งข้อความยืนยันแบบ asynchronous และ retry ไม่เกิน 3 ครั้งภายใน 10 นาที (`IF-NOT-01`, `FR-BKG-05`, `NFR-REL-02`)

รายละเอียด error response ของ IDP/HIS และการเลือก SMS/LINE ยังไม่กำหนดจนกว่าจะตอบ `Q-05` และ `Q-06`

## 7. ลำดับงาน

1. ยืนยันขอบเขตและคำตอบของ `Q-01`, `Q-03` ถึง `Q-08` ก่อนล็อกแบบที่ได้รับผลกระทบ (`FR-BKG-02`, `FR-BKG-03`, `FR-BKG-06`, `IF-IDP-01`, `IF-HIS-01`, `IF-NOT-01`)
2. เตรียม MySQL และโมเดล `Booking`, `Package`, `TimeSlot`, `NotificationDelivery`, `AuditLog` (`CON-TECH-01`, `DOM-PDPA-01`, `IF-HIS-01`)
3. สร้าง API/หน้าจอค้นหาช่วงเวลาว่างและเปลี่ยนแพ็กเกจ (`FR-BKG-01`, `FR-BKG-06`)
4. สร้างการตรวจคิวเดิมและ flow ยืนยันการจอง (`FR-BKG-02`, `AC-BKG-02`, `FR-BKG-04`, `AC-BKG-01`)
5. เพิ่มการป้องกันการจองซ้อนและข้อเสนอช่วงเวลาใกล้เคียง (`FR-BKG-03`, `AC-BKG-03`)
6. เพิ่มการออกหมายเลขคิวสัมพันธ์กับแพ็กเกจและรีเซ็ตรายวัน (`FR-BKG-04`, `ASM-03`)
7. เพิ่ม Worker แจ้งเตือนแบบ asynchronous และ retry (`FR-BKG-05`, `NFR-REL-02`, `AC-BKG-04`, `IF-NOT-01`, `ASM-04`)
8. เพิ่ม audit log, TLS และตรวจคุณภาพด้านประสิทธิภาพ/การใช้งาน (`DOM-PDPA-01`, `NFR-SEC-01`, `NFR-PERF-01`, `NFR-USE-01`, `AC-BKG-05`, `AC-BKG-06`)
9. รัน test ตาม `AC-BKG-01` ถึง `AC-BKG-06` และตรวจ traceability ของทุก FR/NFR/Constraint (`FR-BKG-01` ถึง `FR-BKG-06`)

## 8. สิ่งที่ยังไม่ทำ

ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

- `Q-01` "ช่วงเวลาใกล้เคียง" นับเฉพาะวันเดียวกัน หรือรวมวันถัดไปด้วย? -> ถามพยาบาลคัดกรอง
- `Q-03` ผู้รับบริการที่ใช้คิวเดิมไปแล้วสามารถจองคิวซ้ำในวันเดียวกันได้หรือไม่? -> ถามทีมเอง / เจ้าหน้าที่เวชระเบียน
- `Q-04` เมื่อเปลี่ยนแพ็กเกจ ระบบต้องคำนวณช่วงเวลาว่างจากกฎหรือข้อมูลใด และถ้าเวลาเดิมไม่ว่างแล้วต้องทำอย่างไร? -> ถามผู้ดูแลตารางตรวจ / ทีมเอง
- `Q-05` หาก IDP หรือ HIS ไม่ตอบสนอง ระบบต้องปฏิเสธการเข้าฟีเจอร์ แสดงข้อความใด และให้ลองใหม่ได้หรือไม่? -> ถามผู้ดูแลระบบยืนยันตัวตน / ผู้ดูแล HIS
- `Q-06` ระบบต้องเลือก SMS หรือ LINE อย่างไร? -> ถามทีมเอง / ผู้ดูแลระบบแจ้งเตือน
- `Q-07` การจับเวลา 3 นาทีของ Goal และ NFR-USE-01 เริ่มและจบที่ขั้นตอนไหน และใช้เกณฑ์เดียวกันหรือไม่? -> ถามทีมเอง
- `Q-08` ต้องบันทึก audit log เมื่อใดบ้าง ใครเป็น "ผู้เข้าถึง" และต้องตรวจสอบการเก็บ log ครบอย่างน้อย 1 ปีอย่างไร? -> ถามเจ้าหน้าที่คุ้มครองข้อมูล / ทีมเอง

ส่วนที่เกี่ยวข้องกับ `Q-01`, `Q-03` ถึง `Q-08` จะยังไม่สร้างจนกว่าจะได้คำตอบ และจะไม่เพิ่มหรือตัดสินใจแทน ID ใน `spec.md`
